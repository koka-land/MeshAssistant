# GEMINI.md — MeshAssistant («МЭШ Ассистент»)

## 1. Главная цель и логика работы

**MeshAssistant** — расширение для Google Chrome (Manifest V3, интерфейс на базе Chrome Side Panel) для автоматизации рутинных задач учителя в электронном журнале МЭШ (`school.mos.ru`).

### Основная логика

* **Автоматизация выставления «Учебных умений» (soft skills)** в двух режимах:


* **Фоновый режим (`background`):** быстрый обход через внутренние API МЭШ (`school.mos.ru/api/ej/core/teacher/v1/...` и `POST /api/soft_skills/v1/survey`) с авторизацией через куки (`aupd_token`, `profile_id`, `aid`, `subsystem_id`).


* **Режим реального времени (`ui`):** наглядный обход учеников кликами по строкам таблицы и модальным окнам в DOM.




* **Единый алгоритм расчёта (`calculateAnswers`):** формирует ответы по 4 группам (`Самоорганизация`, `Самообразование`, `Саморегуляция`, `Коммуникация`) на основе среднего взвешенного балла, количества оценок, доли выполненных ЦДЗ (`hwRatio`), доли пропусков (`absenceRatio`, `unexcusedRatio`), нестабильности оценок и результатов важных работ.


* **Управление выполнением:** пересчёт уже выставленных умений (`forceRecalc`), обход всех классов подряд (`processAll`), пауза/возобновление, остановка с автозакрытием модальных окон и вывод итоговой статистики.


* **Настройки (`chrome.storage.local`):** выбор темы (`mesh`, `light`, `dark` + автоизвлечение палитры из бокового меню МЭШ через `extractJournalTheme`), масштаб шрифта (`--font-offset` от `-2px` до `+2px`), настраиваемые пороги оценок и пропусков.


* **Контекстный UI:** на странице журнала конкретного класса отображается аккордеон ассистентов (`assistantsAccordion`), на остальных страницах — заглушка с быстрыми ссылками перехода.

## 2. Принятые архитектурные решения и соглашения по коду

### Структура и ответственность файлов

* **`background.js`:** настройка Side Panel (`openPanelOnActionClick: true`), отслеживание смены вкладок и URL (`onActivated`, `onUpdated`) с кэшем `lastSyncedStateByTab`, динамическая инъекция `content.js` через `chrome.scripting.executeScript`, маршрутизация сообщений между `sidepanel.js` и `content.js`.


* **`content.js`:** обёрнут в IIFE, защищён от повторной подписки флагом `window.meshRobotListenerAdded`, содержит единый расчётчик, API/UI-обработчики и детектор контекста страницы.


* **`sidepanel.js`:** управляет вкладками, настройками, фабрикой карточек-аккордеонов (`createAssistantCard`), ретраями проверки контекста (`requestPageContextWithRetry`) и состояниями UI (`neutral`, `success`, `error`, `paused`).


* **`css/panel-base.css`:** базовые стили целиком на CSS-переменных (`--bg`, `--surface`, `--text`, `--muted`, `--border`, `--primary`, `--tabs-bg` и др.) и адаптивном корневом шрифте `calc(clamp(14px, 3.4vw, 18px) + var(--font-offset))`.



### Зафиксированные решения по UI и CSS (`css/panel-base.css`)

* **Скроллбар без сдвига макета:** у `.tab-pane` заданы `overflow-y: scroll; scrollbar-gutter: stable;` с компенсацией ширины скроллбара (`4px`): `padding-left: 0.5rem; padding-right: calc(0.5rem - 4px);`. Ползунок прозрачен в покое и проявляется (`var(--border)`) при `:hover` и `:focus-within`. Дубликаты правил `::-webkit-scrollbar*` запрещены.


* **Плавное затухание контента при прокрутке:**
* От `mask-image` и glassmorphism (`backdrop-filter`) на `.tabs` и `.panel-footer` отказались (маска затеняла верхнюю карточку в покое и скроллбар; стекло при одинаковой ширине блоков не давало нужного эффекта).
* Принятое решение: мягкий градиент на `.tabs::after` (сверху вниз, `height: 1.45rem`, `linear-gradient(to bottom, var(--bg) 18%, transparent 100%)`) и `.panel-footer::before` (снизу вверх) с `pointer-events: none` и `z-index: 4` на `.top-bar`, `.tabs`, `.panel-footer`.
* Для `.tab-pane` используется компенсация `margin: -0.45rem -0.5rem; padding-top: 1.15rem; padding-bottom: 1.15rem;` — карточки в крайних положениях скролла остаются полностью чёткими, а при прокрутке плавно растворяются.



### Зафиксированные решения по Chrome API и контексту

* **Изоляция окон Chrome:** при клике по `.link-btn[data-url]` в `sidepanel.js` запрашивается текущее окно через `await chrome.windows.getCurrent()` и передаётся `windowId: win.id` в сообщение `open_url`. В `background.js` обработчик `open_url` ищет/создаёт вкладку строго в рамках `windowId` (или `currentWindow: true`), без глобального `chrome.tabs.query({})`.
* **Строгое определение журнала класса:**
* Регулярное выражение `/\/(?:journal\/my|grade)\/\d+/` отличает журнал конкретного класса (`/teacher/study-process/journal/my/<id>`) от общей страницы журналов (`/teacher/study-process/journal/my`) и расписания (`/teacher/account/schedule`).
* В `content.js` (`detectJournalContext`) `isClassJournal` вычисляется как `onSpecificClassUrl || (onJournalSection && hasClassSelector)` (селектор `[data-test-component="leftControlHeadSelectGroup-selectSingleWrapper"]`).


* В `background.js` проверка URL переведена на `isClassJournalUrl` с тем же регулярным выражением.

## 5. Предпочтения пользователя по стилю кода и формату ответов

* **Стиль кода:**
* Чистая модульная архитектура без дублирования правил (особенно в CSS) и без хардкода цветов — всё через CSS-переменные и систему тем.


* Высокие требования к визуальной аккуратности и геометрии UI (ровные отступы, отсутствие артефактов на карточках в покое, предсказуемый скроллбар).


* **Формат ответов:**
* Прямолинейный и практичный тон, без лишних вступлений и «воды».
* Перед кодом — короткое и точное объяснение первопричины проблемы (в CSS, DOM или Chrome API).
* При заметных правках предпочтительно выдавать готовый обновлённый файл целиком, а не разрозненные фрагменты.
* Быстрые итерации по скриншотам и реальному поведению в браузере.
